## 1. Общие сведения

### 1.1. Назначение
Приложение помогает ведущему (судье) проводить офлайн-игры в спортивную мафию за столом на 10 игроков. Оно заменяет бумажный бланк судьи, секундомер и отдельный плеер. Приложение ведёт игру по фазам, считает голоса и баллы, хранит историю игр и статистику игроков.

### 1.2. Цели
1. Ведущий видит всю актуальную информацию по игре на одном экране.
2. Ведущий меньше ошибается: порядок речей, подсчёт голосов, фолы и условия победы контролирует приложение.
3. Протокол игры и баллы формируются автоматически.
4. Копится статистика игроков. Она станет основой функционала для игроков на втором этапе.

### 1.3. Пользователи
| Роль | Этап | Описание |
|---|---|---|
| Ведущий (судья) | 1 | Основной пользователь. Управляет игрой с iPad или ноутбука. |
| Администратор клуба | 1–2 | Ведёт базу игроков, настраивает регламент, смотрит рейтинг. На первом этапе это тот же ведущий. |
| Игрок | 2 | Смотрит свою статистику, историю игр и рейтинг с телефона. |

### 1.4. Термины
| Термин | Значение |
|---|---|
| Красные | Команда мирных: 6 мирных жителей и шериф. |
| Чёрные | Команда мафии: 2 мафии и дон. |
| Круг | Пара «день + ночь». Нумерация: Ночь 0 (знакомство), День 1, Ночь 1, День 2 и так далее. |
| Выставление | Игрок во время своей речи выдвигает кандидатуру на голосование. |
| Попил (автокатастрофа) | Равенство голосов между несколькими кандидатами. |
| Подъём | Игрок покидает игру по итогам голосования. |
| Отстрел | Мафия убивает игрока ночью. |
| Промах | Мафия показала разные номера, и ночью никто не убит. |
| ЛХ (лучший ход) | Игрок, убитый в первую ночь, называет трёх подозреваемых. Угаданные чёрные дают ему доп. баллы. |
| Фол | Замечание за нарушение правил. |
| ППК | Признание поражения команды. Это решение ведущего о поражении команды из-за грубого нарушения её игрока. |
| Доп. баллы | Баллы, которые ведущий выставляет игрокам за качество игры. |
| Регламент | Набор правил и параметров: тайминги, правила голосования, система баллов. |

## 2. Игровая модель, которую реализует приложение

Ниже описан порядок игры, на который опирается логика приложения. За основу взяты правила ФИИМ. Почти все параметры вынесены в настройки регламента, чтобы клуб мог играть по своим правилам. Клубные отличия сверим с ведущим позже.

### 2.1. Состав
- За столом 10 игроков на местах с 1 по 10.
- Роли: 6 мирных, 1 шериф, 2 мафии, 1 дон.
- Ведущий один и сам не играет.

### 2.2. Ночь 0 (знакомство)
1. «Мафия просыпается». Мафия договаривается, по умолчанию 60 с. Играет музыка.
2. «Дон просыпается». Дон знакомится с ведущим, по умолчанию 10 с.
3. «Шериф просыпается». Шериф смотрит на стол, по умолчанию 10 с.
4. «Город просыпается».

### 2.3. День
1. Начиная со Дня 2, ведущий объявляет итоги ночи. Убитый получает прощальную речь на 60 с. Если это первая ночь и регламент включает ЛХ, убитый перед речью называет три номера.
2. Живые игроки говорят по очереди, по 60 с.
   - День 1 начинает игрок №1.
   - Каждый следующий день начинает следующий живой игрок после того, кто начинал предыдущий день.
3. Во время своей речи игрок может выставить одну кандидатуру. Выставленную кандидатуру нельзя снять. Нельзя выставить уже выставленного или выбывшего игрока. Можно выставить самого себя.
4. После всех речей ведущий оглашает кандидатуры в порядке выставления.
5. Проходит голосование по правилам из 2.4.
6. Каждый поднятый игрок получает прощальную речь на 60 с. Это действует и тогда, когда его уход завершает игру.
7. Приложение проверяет условие победы.

### 2.4. Голосование
- Голосуют все живые игроки, каждый ровно один раз.
- Голосуют за кандидатов в порядке выставления.
- Голоса тех, кто не проголосовал, уходят последнему кандидату.
- В День 1 при единственной кандидатуре голосование не проводится.
- Начиная со Дня 2, единственный кандидат покидает стол без голосования. **[уточнить]**
- Если кандидатур нет, голосования нет.
- **Попил.** При равенстве голосов у лидеров порядок такой:
  1. Каждый из них получает оправдательную речь на 30 с.
  2. Проходит переголосование только между ними.
  3. При повторном равенстве проходит голосование «за подъём всех». Если «за» больше половины живых игроков, уходят все участники попила. Иначе не уходит никто.
- Особые случаи при 3–4 живых игроках настраиваются в регламенте. **[уточнить]**

### 2.5. Ночь N (начиная с Ночи 1)
1. «Мафия выходит на охоту». Каждый живой чёрный показывает номер.
   - Если все показали один номер, этот игрок убит.
   - Если номера разные или кто-то не показал, это промах.
2. Дон проверяет одного игрока на шерифа, по умолчанию 10 с. Ведущий показывает результат жестом.
3. Шериф проверяет одного игрока на принадлежность к мафии, по умолчанию 10 с.

Дон и шериф, убитые этой ночью, всё равно делают проверку: о смерти игрок узнаёт только утром.

Если дон или шериф выбыл раньше, его фаза ночью всё равно проходит: ведущий объявляет её и выдерживает паузу по таймеру. Так игроки не поймут по ходу ночи, что роль выбыла. Проверки в такой фазе нет.
4. Всю ночь играет музыка.

### 2.6. Фолы и удаления
| Событие | Последствие по умолчанию (настраивается) |
|---|---|
| 1-й и 2-й фол | Только фиксация. |
| 3-й фол | Игрок пропускает ближайшую речь. При малом числе живых речь может сокращаться до 30 с. **[уточнить]** |
| 4-й фол | Удаление из игры без прощальной речи. |
| Дисквалифицирующий фол | Немедленное удаление без прощальной речи. |
| Удаление днём до голосования | Голосование в этот день не проводится. **[уточнить]** |
| ППК | Игра завершается победой другой команды. |

### 2.7. Условия победы
- Красные побеждают, когда выбыли все чёрные.
- Чёрные побеждают, когда живых чёрных столько же, сколько живых красных.
- Если исход решён голосованием или ночным отстрелом, выбывший игрок сначала получает прощальную речь на 60 с, затем игра завершается.
- Если исход решён удалением игрока за фолы или дисквалификацией, игра завершается сразу. Удалённый игрок прощальной речи не получает.
- Ведущий может завершить игру вручную, например при ППК.

### 2.8. Подсчёт баллов
Система баллов настраивается в регламенте. Значения ниже приняты как стартовые. **[уточнить с ведущим]**

| Составляющая | Значение по умолчанию |
|---|---|
| Победа команды | +1 каждому игроку победившей команды |
| Поражение | 0 |
| Доп. баллы ведущего | Ведущий вводит вручную. Диапазон и шаг задаются в регламенте. |
| ЛХ: 2 чёрных из 3 | +0,25 |
| ЛХ: 3 чёрных из 3 | +0,5 |
| Компенсация первому убитому | Отключена. Можно включить и задать формулу. |
| Удаление за 4 фола или дисквалификацию | Штраф, значение задаётся в регламенте |
| ППК | Штраф виновному игроку, значение задаётся в регламенте |

Итог игрока = победа + доп. баллы + ЛХ + компенсация − штрафы.

## 4. Функциональные требования MVP

### 4.1. База игроков
- Добавление, редактирование и архивация игроков. Поля: никнейм (обязательно), имя, фото, заметка.
- Поиск по нику при рассадке.
- Быстрое добавление нового игрока прямо с экрана рассадки.
- Защита от дублей ников.

### 4.2. Создание игры
1. Ведущий выбирает регламент: готовый пресет или свой.
2. Ведущий рассаживает игроков по местам 1–10. Есть случайная рассадка и перестановка мест перетаскиванием.
3. Ведущий вводит роль каждого игрока по вытянутым карточкам. Опционально приложение раздаёт роли случайно.
4. Приложение проверяет состав: ровно 6 мирных, 1 шериф, 2 мафии, 1 дон. Без этого игру не запустить.
5. У игры есть поля: дата, время, клуб или место, ведущий, номер игры в вечере.

### 4.3. Главный экран ведущего
**Шапка показывает:**
- текущую фазу и круг, например «День 2 · Речи» или «Ночь 1 · Проверка шерифа»;
- номер говорящего игрока;
- большой таймер;
- число живых красных и чёрных.

**Стол.** 10 мест кругом или сеткой. Для каждого места видно:
- номер и ник;
- роль цветом и иконкой;
- статус: жив, убит ночью, поднят голосованием, удалён;
- количество фолов;
- отметку «выставлен» и номер того, кто выставил;
- отметки проверок шерифа и дона с результатом.

**Скрытие ролей.** Переключатель «скрыть роли» защищает на случай, если игроки видят экран. Пока он включён, роль видна только при удержании пальца на месте.

**Панель действий.** Кнопки для текущей фазы, например «Следующий игрок», «Выставить», «Фол», «К голосованию».

**Подсказка ведущему.** Текст того, что сейчас говорить: «Мафия просыпается…», «Голосуем за игрока №5…».

### 4.4. Ведение игры по фазам
- Приложение ведёт игру как сценарий по правилам раздела 2. Следующая фаза подставляется автоматически.
- Ведущий может вручную перейти к любой фазе, если игра пошла нестандартно.
- Порядок речей считается автоматически. Выбывшие и пропускающие речь за 3-й фол пропускаются.
- Приложение автоматически:
  - проверяет условия победы после каждого выбывания;
  - запрещает повторное выставление;
  - напоминает о пропуске речи за 3-й фол;
  - блокирует голосование в случаях из раздела 2.4.

### 4.5. Таймер
- Длительности берутся из регламента: речь 60 с, оправдание 30 с, прощальная речь 60 с, договорка 60 с, ночные проверки 10 с.
- Управление: старт, пауза, сброс, +10 с, досрочное завершение.
- Звуковой сигнал звучит за 10 с до конца и в конце. Каждый сигнал можно отключить. На устройствах с вибрацией есть вибросигнал.
- На последних 10 секундах таймер меняет цвет.
- Можно включить автостарт таймера при переходе к следующему игроку.

### 4.6. Выставления
- Выставление привязано к речи текущего игрока. Ведущий нажимает на место за столом или вводит номер.
- Кандидаты хранятся в порядке выставления.
- Ошибочное выставление можно снять в любой момент во время речей и на голосовании, пока не введены голоса. После снятия на голосовании приложение заново решает, нужно ли голосование.

### 4.7. Голосование
- Ведущий вводит число голосов за каждого кандидата крупными кнопками-цифрами. Кто за кого голосовал, не фиксируется.
- Приложение показывает, сколько голосов ещё не отдано: живые игроки минус уже введённые голоса.
- Оставшиеся голоса приложение автоматически отдаёт последнему кандидату. Ведущему не нужно вводить их вручную.
- Приложение не даёт ввести голосов больше, чем живых игроков.
- Приложение само определяет результат: подъём, попил, переголосование или голосование «за подъём всех».
- Итог голосования показывается крупно перед подтверждением.

### 4.8. Ночь
- **Выстрел.** Ведущий вводит только итог: нажимает на место убитого игрока или кнопку «Промах». Ввод номера от каждого мафиози можно добавить позже как опцию.
- **Проверка дона.** Ведущий вводит номер. Приложение крупно показывает «ШЕРИФ» или «НЕ ШЕРИФ».
- **Проверка шерифа.** Ведущий вводит номер. Приложение показывает «МАФИЯ» или «МИРНЫЙ».
- Результаты проверок сохраняются и видны на столе ведущего.
- Подсказки и таймеры ночи идут по сценарию.

### 4.9. Фолы, удаления, ППК
- Фол ставится и снимается одним касанием на месте игрока.
- Последствия 3-го и 4-го фола применяются автоматически по регламенту.
- «Дисквалификация» и «ППК» вынесены в отдельные действия. Оба требуют подтверждения.
- Протокол фиксирует фазу, в которой выдан фол. Можно указать короткую причину.

### 4.10. Лучший ход
- ЛХ включается, если первая смерть в игре — отстрел в Ночь 1. **[уточнить точное условие по регламенту]**
- Ведущий вводит три номера. Приложение считает угаданных чёрных и начисляет баллы.

### 4.11. Завершение игры и баллы
- Приложение само объявляет победу команды по условию из 2.7. Ведущий подтверждает.
- После игры открывается экран итогов:
  - все роли раскрыты;
  - ведущий вводит доп. баллы каждому игроку;
  - приложение считает итог по формуле регламента.
- Игру можно сохранить как черновик и вернуться к доп. баллам позже.

### 4.12. Протокол игры
Макет протокола сверстаем по бумажному бланку судьи клуба. Бланк запрошен, раздел уточним после его получения. **[ожидаем бланк]**

- Протокол формируется автоматически. В нём есть:
  - рассадка и роли;
  - фолы;
  - выставления и голосования по дням;
  - отстрелы, проверки дона и шерифа;
  - ЛХ, победитель, баллы.
- Полный журнал событий хранится со временем каждого события.
- Протокол экспортируется в PDF и в картинку, удобную для отправки в Telegram.
- Данные экспортируются в CSV и JSON.

### 4.13. Отмена и исправление
- Кнопка «Отменить» отменяет последнее действие. Глубина отмены в пределах игры не ограничена.
- Отменённое действие можно вернуть.
- Прошлое событие можно исправить из журнала, например неверно введённый голос. Состояние игры пересчитывается.

### 4.14. Музыка и звуки
- Ведущий загружает свои аудиофайлы (mp3, m4a, ogg). Файлы хранятся на устройстве.
- Плейлисты по назначению: «Договорка», «Ночь», «Победа красных», «Победа чёрных», «Фон между играми».
- С началом ночи музыка запускается автоматически. С наступлением дня она плавно затухает.
- Есть два режима: продолжать трек с места остановки или включать новый трек каждую ночь. Есть перемешивание.
- Мини-плеер всегда на экране: пауза, следующий трек, громкость.
- Встроенные звуки сигналов таймера можно заменить своими.

Стриминговые сервисы вроде Яндекс Музыки и Spotify в MVP не встраиваются. Их нельзя надёжно использовать офлайн и легально встроить в приложение.

### 4.15. Статистика
**По текущей игре** ведущий видит для каждого игрока:
- фолы;
- кого он выставлял;
- сколько голосов против него было в каждом голосовании;
- проверки.

**По игроку за всё время** из локальной базы:
- игры, победы и процент побед, всего и отдельно за мирного, шерифа, мафию, дона;
- сумма баллов и средний балл, сумма и среднее доп. баллов;
- сколько раз убит в первую ночь, количество и точность ЛХ;
- фолы и удаления;
- для шерифа: сколько чёрных найдено;
- для дона: в какую ночь найден шериф;
- для красных: доля выставлений чёрных игроков.

**Рейтинг клуба.** Таблица игроков с сортировкой по сумме баллов, среднему баллу и проценту побед. Есть фильтр по периоду.

**Игровой вечер.** Сводная таблица по серии игр вечера с суммой баллов.

### 4.16. Настройки
**Регламенты:**
- встроенный пресет «ФИИМ (базовый)»;
- создание своего регламента на основе пресета;
- все тайминги, правила голосования, фолов, ЛХ и баллов из раздела 2.

**Интерфейс:**
- тема: тёмная по умолчанию или светлая;
- размер шрифта;
- вид стола: круг или сетка;
- автостарт таймера.

**Звук:** громкость музыки и сигналов, длительность затухания.

**Данные:**
- резервная копия всей базы в файл;
- восстановление из файла;
- очистка.

| Требование | Описание |

| Устройства | Ведущий работает на iPad в горизонтальной ориентации или на ноутбуке. Работа ведущего с телефона не требуется. Интерфейс игроков на втором этапе делается для телефонов. |

| Защита от ошибок | Опасные действия требуют подтверждения: удаление, ППК, завершение игры. Любое действие можно отменить. |
| Язык | Русский. Архитектура позволяет добавить другие языки. |
| Скрытность ролей | При включённом скрытии роли видны только по явному действию ведущего. |

## 6. Экраны MVP

1. **Главное меню:** новая игра, продолжить игру, история, игроки, рейтинг, настройки.
2. **Игроки:** список, карточка игрока со статистикой, редактирование.
3. **Новая игра:** выбор регламента, рассадка, роли.
4. **Игровой экран:** стол, шапка с фазой и таймером, панель действий, подсказка, мини-плеер.
5. **Голосование:** отдельный режим игрового экрана.
6. **Ночь:** отдельный тёмный режим игрового экрана с вводом выстрелов и проверок.
7. **Итоги игры:** роли, доп. баллы, расчёт баллов, сохранение.
8. **Протокол:** просмотр и экспорт.
9. **История игр:** список, фильтры, открытие протокола.
10. **Рейтинг и игровой вечер.**
11. **Настройки и регламенты.**
12. **Музыка:** библиотека и плейлисты.

## 7. Модель данных верхнего уровня

| Сущность | Основные поля |
|---|---|
| Игрок | id, ник, имя, фото, заметка, признак архива |
| Регламент | id, название, тайминги, правила голосования, правила фолов, система баллов |
| Игра | id, дата, ведущий, регламент, номер в вечере, статус, победитель |
| Место в игре | игра, номер места, игрок, роль, итоговый статус, фолы, баллы по составляющим |
| Событие игры | игра, порядковый номер, время, фаза, тип, данные |
| Игровой вечер | id, дата, место, список игр |
| Турнир | id, название, даты, столы, заранее составленные рассадки по турам, список игр. Режим турнира делается на этапе 1.5, но сущность заложена сразу. |
| Трек и плейлист | файл, название, назначение плейлиста, порядок |

Состояние игры полностью вычисляется из журнала событий. Поэтому отмена, исправление прошлых действий, протокол и статистика реализуются просто.

## 8. Платформа и технологии (предложение)

**Решение: прогрессивное веб-приложение (PWA).**
- Оно устанавливается на iPad и ноутбук как обычное приложение и работает офлайн.
- Один код работает на iPad, Windows и macOS. Публикация в App Store не нужна.
- На втором этапе тот же код откроется на телефонах игроков как личный кабинет.

| Слой | Технология |
|---|---|
| Интерфейс | React + TypeScript, Vite |
| Локальное хранилище | IndexedDB для игр, игроков и аудиофайлов |
| Офлайн-режим | Service Worker |
| Экспорт | Генерация PDF и PNG на устройстве |
| Этап 2 | Сервер с базой PostgreSQL. Конкретный стек выберем к началу этапа. |

**Ограничения iPad, которые учитываем:**
- Музыка и таймер работают, пока приложение открыто на экране. Если свернуть его, iPadOS может остановить звук. Ведущий во время игры держит приложение открытым.
- Запрет сна экрана в установленном веб-приложении поддерживается в свежих версиях iPadOS. На старых версиях нужно отключить автоблокировку в настройках iPad. Приложение подскажет это при первом запуске.
- Звук в Safari можно включить только после касания экрана. Поэтому музыка «разблокируется» при старте игры.

Если на реальном iPad эти ограничения окажутся критичными, приложение можно обернуть в нативную оболочку для iOS без переписывания интерфейса.

## 9. Этапы 1.5 и 2 (кратко, детализируем позже)

### 9.1. Этап 1.5: расширения ведущего
- **Турнирный режим.** Заранее составленные рассадки на серию игр, несколько столов, общая турнирная таблица.
- **Голосовые подсказки.** Приложение озвучивает фразы ночи, чтобы ведущему не говорить в темноте.
- **Расширенная статистика.** Графики, сравнение игроков, статистика пар игроков. При необходимости сюда можно добавить поимённый ввод голосов.

### 9.2. Этап 2: функционал игроков
- Сервер и синхронизация данных с устройств нескольких ведущих одного клуба.
- Интерфейс игрока рассчитан на телефон.
- Аккаунт игрока со входом через Telegram или по телефону. Аккаунт привязывается к нику в базе клуба.
- Личный кабинет: статистика, история игр с протоколами, динамика рейтинга.
- Публичный рейтинг клуба.
- Запись на игры и уведомления, возможно через Telegram-бота.

## 10. Что не входит в MVP
- Онлайн-игра и видеосвязь.
- Аккаунты, сервер, синхронизация между устройствами.
- Оплата и продажа билетов.
- Встраивание стриминговых музыкальных сервисов.
- Несколько столов одновременно.
- Поимённый учёт голосов.
- Экран зала для игроков. Он не предусмотрен ни на одном этапе.

## 11. Вопросы к заказчику

**Вопросы к ведущему клуба.** Их не нужно решать до начала разработки, все эти параметры настраиваются.
1. **Клубные отличия от правил ФИИМ.** Сверить пункты раздела 2 с пометкой «[уточнить]»:
   - единственный кандидат со Дня 2;
   - особые случаи голосования при 3–4 живых;
   - речь после 3-го фола при малом числе живых;
   - голосование в день удаления игрока;
   - точное условие лучшего хода.
2. **Баллы.** Подтвердить числа из раздела 2.8.
3. **Бланк судьи** для макета протокола.
4. **Оформление.** Название, логотип, цвета клуба. Пока делаем нейтральное оформление.

**Решения:**
| Вопрос | Решение | Версия |
|---|---|---|
| Устройство ведущего | iPad или ноутбук. Игроки на втором этапе — телефоны. | 0.2 |
| Ввод голосов | Только количество голосов. | 0.2 |
| Экран зала | Не предусмотрен. | 0.2 |
| Хранение данных | На одном устройстве с резервной копией в файл. | 0.2 |
| Регламент | Правила ФИИМ, клубные отличия подгоним позже. | 0.3 |
| Баллы | Значения из раздела 2.8 принимаются как стартовые. | 0.3 |
| Выстрел | Ведущий вводит только итог: «убит №X» или «промах». | 0.3 |
| Турниры | Возможны. Модель данных учитывает турниры с первой версии, сам режим делается на этапе 1.5. | 0.3 |
| Оформление | Своего пока нет, делаем нейтральное. | 0.3 |
| Выставление себя | Разрешено. | 0.4 |
| Проверки убитых ночью дона и шерифа | Делаются в ту же ночь. | 0.4 |
| Прощальная речь при завершении игры | Есть, 60 с, если игрок ушёл голосованием или отстрелом. | 0.4 |
| Фазы выбывших дона и шерифа ночью | Проходят как обычно, с паузой по таймеру и без проверки. | 0.5 |

## 12. Критерии приёмки MVP
1. Ведущий проводит полную игру от рассадки до итогов без бумажного бланка и отдельного секундомера.
2. Приложение верно определяет порядок речей, итоги голосования с попилом, итоги ночи и победителя во всех сценариях из раздела 2.
3. После закрытия приложения или перезагрузки устройства игра восстанавливается с того же места.
4. Любое действие можно отменить. Ошибку в прошлом действии можно исправить, и игра пересчитается.
5. Все функции работают без интернета.
6. Музыка автоматически запускается ночью и затухает днём.
7. Баллы считаются по регламенту. Протокол экспортируется в PDF.
8. Статистика игрока и рейтинг клуба строятся по сохранённым играм.
